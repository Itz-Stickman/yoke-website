The Yoke API

See what's playing and control Yoke from your own app: stream overlays, Stream Deck and Streamer.bot buttons, desktop widgets, chat bots and more.

Needs Yoke 1.5 or later on Windows.

Getting started

  1. In Yoke, open Settings → Advanced → Yoke API and switch on Turn on the Yoke API.
  2. Click Create API key…, name it after your app and pick what it may do. Copy the key (it starts with yk_). It's only shown once.
  3. Send requests to http://127.0.0.1:47321/api/v1. The exact address, including the port, is shown in Yoke's settings.
curl -H "Authorization: Bearer yk_YOUR_KEY" http://127.0.0.1:47321/api/v1/player
The API only answers on the PC running Yoke. To reach it from another device, the user turns on Settings → Advanced → Local network, then you use the PC's network address (shown in settings). Requests and replies are JSON. Cross-origin requests are allowed, so browser pages and overlays can call it directly.

Authentication

Every request needs a key, sent in one of these ways:

WhereExample
Header (preferred)Authorization: Bearer yk_…
HeaderX-Yoke-Key: yk_…
Query string (WebSockets, overlays)?key=yk_…

Each key has one or more permissions, chosen by the user:

PermissionAllows
readPlayer state, queue, library, playlists, live events
controlPlay, pause, skip, seek, volume, mute, shuffle, repeat, changing the queue
playlistsCreating playlists and adding or removing songs
Treat keys like passwords. Users can delete a key at any time, which ends every request and live connection using it.

Errors

Errors use normal HTTP status codes with a JSON body:

{ "error": "forbidden", "message": "This API key doesn't have the \"control\" permission." }
StatuserrorMeaning
400bad_request, unknown_commandSomething in the request is missing or wrong; message says what
401unauthorizedNo key, or the key doesn't exist (deleted?)
403forbiddenThe key doesn't have the needed permission
404not_foundNo such track, playlist or endpoint
409nothing_playing, nothing_to_playThe action needs a song loaded
503api_disabled, no_playerThe user turned the API off, or the player isn't running
504timeoutThe player didn't answer in time; try again

Objects

Track

{
  "id": "77f527e361909294",
  "title": "Fire Away",
  "artist": "Artist Name",
  "albumArtist": "Artist Name",
  "album": "Album Name",
  "trackNo": 3, "discNo": 1, "year": 2024, "genre": "Rock",
  "duration": 213.4,
  "addedAt": 1761700000000,
  "coverUrl": "/api/cover/77f5…?v=e"
}

duration is in seconds. addedAt is milliseconds since 1970, or null. coverUrl is relative to the server, null if there's no cover, and needs no key.

Player state

{
  "playing": true,
  "track": { …Track… },
  "position": 42.7,
  "duration": 213.4,
  "volume": 0.8,
  "muted": false,
  "shuffle": false,
  "repeat": "off",
  "queueIndex": 4,
  "queueLength": 25,
  "updatedAt": 1761700123456
}

track is null when nothing is loaded. position and duration are in seconds (position as of updatedAt). volume is 0–1. repeat is "off", "all" or "one". queueIndex is the current song's place in the queue, or -1. updatedAt is milliseconds since 1970.

While playing, the current position is about position + (Date.now() - updatedAt) / 1000.

Playlist

{ "id": "8d7b…", "name": "Road Trip", "trackCount": 12 }

Player

Every control endpoint answers with the new player state.

GET/api/v1any key

Checks the key. Returns { name, version, apiVersion, key: { name, scopes } }.

GET/api/v1/playerread

The current player state.

POST/api/v1/player/play · /pause · /toggle · /next · /previouscontrol

No body needed. play with nothing queued starts the library from the top.

POST/api/v1/player/seekcontrol
{ "position": 60 }

position is in seconds.

POST/api/v1/player/volumecontrol
{ "volume": 0.5 }

volume is from 0 to 1.

POST/api/v1/player/mute · /shuffle · /repeatcontrol
{ "muted": true }
{ "on": true }
{ "mode": "all" }

Leave the body out to toggle mute or shuffle, or to cycle through repeat modes ("off", "all", "one").

Queue

GET/api/v1/queueread

Returns { index, tracks: [Track…] } in play order.

POST/api/v1/queue/playcontrol

Replaces the queue and starts playing. Give tracks or a playlist:

{ "trackIds": ["77f5…", "a1b2…"], "index": 0, "shuffle": false }
{ "playlistId": "8d7b…", "shuffle": true }
POST/api/v1/queuecontrol

Adds to the queue. "next": true plays them right after the current song; otherwise they go at the end.

{ "trackIds": ["77f5…"], "next": true }
POST/api/v1/queue/jumpcontrol
{ "index": 3 }

index starts at 0, so this plays the 4th song in the queue.

Library

GET/api/v1/library/tracksread

Query: search (matches title, artist, album), limit (1–1000, default 100), offset.

GET /api/v1/library/tracks?search=fire&limit=10
→ { "total": 2, "offset": 0, "limit": 10, "tracks": [Track…] }
GET/api/v1/library/tracks/:idread

One track.

GET/api/cover/:idno key

A track's cover image. Use the coverUrl from a track, joined to the server address.

Playlists

GET/api/v1/playlistsread

Returns { playlists: [Playlist…] }.

GET/api/v1/playlists/:idread

The playlist plus tracks: [Track…].

POST/api/v1/playlistsplaylists
{ "name": "Stream picks" }   → 201 with the new playlist
POST/api/v1/playlists/:id/tracksplaylists
{ "trackIds": ["77f5…"] }

Songs already in the playlist are skipped.

DELETE/api/v1/playlists/:id/tracks/:trackIdplaylists

Removes a song from the playlist.

WebSocket events

WSws://127.0.0.1:47321/api/v1/events?key=yk_…read

Get changes the moment they happen instead of polling. Yoke sends:

typeWhendata
helloRight after connecting{ name, version, apiVersion, scopes }
stateOn connect, and whenever playback, volume, shuffle, repeat or the queue changes (about every 5 s while playing)Player state
trackchangeA different song starts{ track }
{ "type": "trackchange", "data": { "track": { "title": "Fire Away", … } } }

With the control permission you can also send commands over the same connection. Add an id to match the reply:

→ { "id": 1, "command": "next" }
← { "id": 1, "ok": true, "state": { … } }

→ { "id": 2, "command": "volume", "args": { "volume": 0.4 } }
→ { "id": 3, "command": "playTracks", "args": { "trackIds": ["77f5…"], "index": 0 } }
→ { "id": 4, "command": "getState" }

getState only needs the read permission.

Commands: play, pause, toggle, next, previous, seek {position}, volume {volume}, mute {muted?}, shuffle {on?}, repeat {mode?}, playTracks {trackIds, index?, shuffle?}, enqueue {trackIds, next?}, jump {index}, getState.

The connection closes with code 4001 if the key is deleted or the API is turned off.

Examples

JavaScript (browser or Node 22+)

const BASE = 'http://127.0.0.1:47321';
const KEY = 'yk_YOUR_KEY';

await fetch(`${BASE}/api/v1/player/next`, { method: 'POST', headers: { Authorization: `Bearer ${KEY}` } });

const ws = new WebSocket(`ws://127.0.0.1:47321/api/v1/events?key=${KEY}`);
ws.onmessage = (e) => {
  const msg = JSON.parse(e.data);
  if (msg.type === 'trackchange') console.log('Now playing:', msg.data.track.title);
};

This skips to the next song, then logs each new song as it starts.

Python

import requests
BASE, KEY = "http://127.0.0.1:47321/api/v1", "yk_YOUR_KEY"
h = {"Authorization": f"Bearer {KEY}"}

state = requests.get(f"{BASE}/player", headers=h).json()
print(state["track"]["title"] if state["track"] else "Nothing playing")
requests.post(f"{BASE}/player/volume", json={"volume": 0.5}, headers=h)

Streamer.bot, Touch Portal and similar

Use an HTTP request action (for example POST …/api/v1/player/toggle with the Authorization header), or a WebSocket client connected to /api/v1/events?key=… to react to trackchange and send commands.
